Setup guide

Quaykeep runs on Windows 10/11, macOS 14+ and 64-bit Linux. It needs nothing else installed: the .NET runtime is inside the package. Sessions outside the built-in terminal use the system's OpenSSH client (ssh), which every supported OS has.

Install

WindowsmacOSLinux

Windows

  1. Download Quaykeep-win-x64-Setup.exe and run it. It installs for your user into %LOCALAPPDATA%\QuaykeepApp (no admin rights) and adds Quaykeep to the Start menu.
  2. If SmartScreen says “Windows protected your PC”, click More info → Run anyway (the installer is not code-signed).

Portable: Quaykeep-win-x64-Portable.zip runs from any folder (a USB stick, C:\Tools) and keeps its data next to itself; it updates itself too.

Already using a zip copy (1.0.x, or SSH Manager)? It keeps updating itself in place, with its data folder. To switch to the installer, exit the old copy from the tray, install, and copy the old data folder to %LOCALAPPDATA%\Quaykeep\data before the first start.

macOS

  1. Download the package for your Mac: Apple Silicon (Apple menu → About This Mac shows “Apple M…”) or Intel.
  2. Open the .pkg. If macOS says it “cannot be opened because Apple cannot check it”, open System Settings → Privacy & Security, scroll down and click Open Anyway, then open the package again. The same may happen on the first start of the app.
  3. Quaykeep is installed as /Applications/Quaykeep.app. Its icon lives in the menu bar; closing the window keeps it running there (the SSH agent keeps working).

Terminal alternative to step 2, for the app after installing: xattr -dr com.apple.quarantine /Applications/Quaykeep.app

Linux

chmod +x Quaykeep-linux-x64.AppImage
./Quaykeep-linux-x64.AppImage

Keep the file somewhere permanent (for example ~/Applications): autostart and the AI-agent setup point at it, and updates replace it in place. Two system libraries may be missing on a fresh desktop:

DistributionCommand
Ubuntu 24.04+, Debian 13sudo apt install libfuse2t64 libwebkit2gtk-4.1-0

FUSE runs the AppImage; WebKitGTK draws the built-in terminal and editor (everything else works without it). On GNOME the tray icon needs the AppIndicator extension (preinstalled on Ubuntu).

First start

Quaykeep asks for a master password: it encrypts the vault with your servers, passwords and keys (AES-256-GCM, key from Argon2id). A forgotten master password cannot be recovered — keep it in your password manager.

It also offers to start at login. Started that way it goes straight to the tray, locked; the unlock window appears the first time you connect or something asks the SSH agent for a key. Change it in Settings → Startup and tray.

Add a server with Ctrl+N (name, host, user, password or key). Right-click a server for everything else: files, install scripts, port forwards, firewall, monitoring, “Set up key login”.

Connecting

Double-click a server (or press Enter). Where the session opens is set in Settings → Terminal:

  • Built-in terminal — tabs in the Quaykeep window with suggestions from the server's history, commands, files, containers and services; edit FILE opens the file in the built-in editor. The default on macOS and Linux.
  • Windows Terminal (tab or window) or a console window — Windows.
  • System terminal — Terminal.app on macOS; on Linux $TERMINAL or the first of x-terminal-emulator, gnome-terminal, konsole, xfce4-terminal, kitty, alacritty, wezterm, foot, xterm.

Servers with a jump host or extra ssh arguments always open in the external terminal (they need OpenSSH). Passwords are passed to ssh through SSH_ASKPASS and keys through the agent: neither appears on a command line or on disk.

AWS SSM

For EC2 instances without an open SSH port: in the server's editor, Advanced → Connect → Through AWS SSM, put the instance ID (i-0123…) as the host and, if needed, the AWS CLI profile and region. The login is still ordinary SSH with a key or password; Session Manager only carries the connection (the AWS-StartSSHSession document), so the built-in terminal, files, scripts and monitoring work as usual.

  • Install AWS CLI v2 and the Session Manager plugin.
  • The instance needs the SSM agent online and sshd running; your AWS role needs ssm:StartSession on AWS-StartSSHSession.
  • AWS SSM shell only (login choice next to Password / SSH key): connecting opens the plain aws ssm start-session in the system terminal, with no SSH and no key left on the server. To get files, scripts and monitoring, use Set up key login…: it installs a key through AWS for the Linux user you name and switches the server to key login through SSM.
  • With AWS SSO, when the sign-in expires, use Sign in to AWS (SSO) in the server's menu (it runs aws sso login and opens the browser).

SSH agent

While Quaykeep runs, its agent hands the vault's keys to ssh, git, VS Code Remote-SSH and anything else that speaks the OpenSSH agent protocol. While the vault is locked, a request opens the unlock window. The exact address is shown in the status bar of the main window.

Windows

The agent takes the standard pipe \\.\pipe\openssh-ssh-agent, which ssh.exe, git and VS Code use without any setup. If another agent already holds it (1Password, the Windows “OpenSSH Authentication Agent” service), Quaykeep uses \\.\pipe\quaykeep-agent-<user>; point programs at it with:

[Environment]::SetEnvironmentVariable('SSH_AUTH_SOCK', '\\.\pipe\quaykeep-agent-user', 'User')

macOS

The agent is a socket at ~/.quaykeep-agent.sock. Add to ~/.zshrc:

export SSH_AUTH_SOCK="$HOME/.quaykeep-agent.sock"

or, for ssh only, to ~/.ssh/config:

Host *
  IdentityAgent ~/.quaykeep-agent.sock

Linux

The socket is $XDG_RUNTIME_DIR/quaykeep-agent.sock (usually /run/user/1000/…), or ~/.quaykeep-agent.sock without XDG_RUNTIME_DIR. Add to ~/.bashrc / ~/.zshrc:

export SSH_AUTH_SOCK="$XDG_RUNTIME_DIR/quaykeep-agent.sock"

Sessions started from Quaykeep get the right agent automatically, whatever your shell says.

The qk command

qk <server> connects to a saved server in the current terminal, qk list lists them, qk cron <server> shows its scheduled jobs. It talks to the running app (and starts it in the tray if needed).

AI agents (MCP)

Turn it on in Settings → AI agents (MCP). The same page has the ready command for your copy with a Copy button; for reference:

# Claude Code — Windows
claude mcp add --scope user quaykeep -- "%LOCALAPPDATA%\QuaykeepApp\current\qk.exe" mcp
# Claude Code — macOS
claude mcp add --scope user quaykeep -- "/Applications/Quaykeep.app/Contents/MacOS/qk" mcp
# Claude Code — Linux (AppImage)
claude mcp add --scope user quaykeep -- "$HOME/Applications/Quaykeep-linux-x64.AppImage" qk mcp
# Codex — ~/.codex/config.toml (macOS example)
[mcp_servers.quaykeep]
command = '/Applications/Quaykeep.app/Contents/MacOS/qk'
args = ["mcp"]
tool_timeout_sec = 900

Then choose per server what the agent may do: right-click → AI agent access ▸ (off by default; read only, read and reboot, menu commands, full access). Reboots and deletions ask you first, and every call is in the agent log. An HTTP endpoint on 127.0.0.1 with a token is also available for clients that can't start a program.

Updates

Once a day Quaykeep checks this project's GitHub releases (Settings → Updates has “Check for updates” and “Update and restart”). Installed copies download only the changes; the update is applied on restart. Your data folder is never part of an update.

Data, backups, moving to another computer

CopyData folder
Windows installer%LOCALAPPDATA%\Quaykeep\data
Windows zipdata next to the program
macOS~/Library/Application Support/Quaykeep/data

QUAYKEEP_DATA=/path overrides it. Settings → Backup zips the whole folder to a local folder or to a server over SFTP (by hand or every N hours). To move to another computer — on any OS — install Quaykeep there and use File → Restore from backup with your master password.

Uninstall

  • Windows: Settings → Apps → Quaykeep → Uninstall. The data folder stays; delete %LOCALAPPDATA%\Quaykeep to remove it.
  • macOS: quit from the menu bar, move /Applications/Quaykeep.app to the Trash, and delete ~/Library/Application Support/Quaykeep and ~/Library/LaunchAgents/app.quaykeep.plist if you want.
  • Linux: exit from the tray, delete the AppImage, ~/.local/share/Quaykeep and ~/.config/autostart/quaykeep.desktop.

Troubleshooting

  • The built-in terminal shows a message about a web engine — Windows: install the WebView2 Runtime (part of Windows 11); Linux: install WebKitGTK (see above); or pick another terminal in Settings.
  • No tray icon on GNOME — enable the AppIndicator extension; the window is still there via the app launcher.
  • “Lock when the computer locks” does nothing on Linux — it listens to the desktop's screen saver and logind over D-Bus; most desktops send it, some minimal window managers don't.
  • The global shortcut (Win+Alt+X) exists on Windows only.
  • Something else? Open an issue.
