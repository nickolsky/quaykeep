Инструкция

Quaykeep работает в Windows 10/11, macOS 14+ и 64-битном Linux. Больше ничего ставить не нужно: среда .NET уже внутри пакета. Сессии вне встроенного терминала используют системный клиент OpenSSH (ssh), он есть в каждой из этих ОС.

Установка

WindowsmacOSLinux

Windows

  1. Скачайте Quaykeep-win-x64-Setup.exe и запустите. Программа ставится для вашего пользователя в %LOCALAPPDATA%\QuaykeepApp (без прав администратора) и появляется в меню «Пуск».
  2. Если SmartScreen пишет «Система Windows защитила ваш компьютер», нажмите Подробнее → Выполнить в любом случае (установщик не подписан).

Портативно: Quaykeep-win-x64-Portable.zip работает из любой папки (флешка, C:\Tools), данные хранит рядом с собой и тоже обновляется сама.

Уже пользуетесь копией из zip (1.0.x или SSH Manager)? Она продолжит обновляться на месте, вместе со своей папкой data. Чтобы перейти на установщик, выйдите из старой копии через трей, установите программу и до первого запуска скопируйте старую папку data в %LOCALAPPDATA%\Quaykeep\data.

macOS

  1. Скачайте пакет для своего Mac: Apple Silicon (меню Apple → «Об этом Mac» показывает «Apple M…») или Intel.
  2. Откройте .pkg. Если macOS пишет, что не может его проверить, откройте Системные настройки → Конфиденциальность и безопасность, прокрутите вниз, нажмите Всё равно открыть и снова откройте пакет. То же может случиться при первом запуске программы.
  3. Quaykeep устанавливается в /Applications/Quaykeep.app. Его значок живёт в строке меню; закрытие окна оставляет программу там (SSH-агент продолжает работать).

Вместо шага 2 для уже установленной программы можно в Терминале: xattr -dr com.apple.quarantine /Applications/Quaykeep.app

Linux

chmod +x Quaykeep-linux-x64.AppImage
./Quaykeep-linux-x64.AppImage

Положите файл в постоянное место (например, ~/Applications): на него указывают автозапуск и настройка ИИ-агентов, а обновления заменяют его на месте. На свежем рабочем столе могут не найтись две системные библиотеки:

ДистрибутивКоманда
Ubuntu 24.04+, Debian 13sudo apt install libfuse2t64 libwebkit2gtk-4.1-0
Ubuntu 22.04, Debian 12sudo apt install libfuse2 libwebkit2gtk-4.1-0
Fedorasudo dnf install fuse-libs webkit2gtk4.1
Archsudo pacman -S fuse2 webkit2gtk-4.1

FUSE запускает AppImage; WebKitGTK рисует встроенные терминал и редактор (всё остальное работает и без него). В GNOME для значка в трее нужно расширение AppIndicator (в Ubuntu оно уже есть).

Первый запуск

Quaykeep попросит мастер-пароль: им шифруется хранилище с серверами, паролями и ключами (AES-256-GCM, ключ из Argon2id). Забытый мастер-пароль восстановить невозможно — сохраните его в менеджере паролей.

Ещё программа предложит запускаться при входе в систему. Запущенная так, она сразу уходит в трей заблокированной; окно разблокировки появляется, когда вы подключаетесь или кто-то просит ключ у SSH-агента. Это меняется в Настройки → Запуск и трей.

Сервер добавляется по Ctrl+N (имя, адрес, пользователь, пароль или ключ). Всё остальное — в меню по правому щелчку: файлы, скрипты установки, пробросы портов, файрвол, мониторинг, «Настроить вход по ключу».

Подключение

Двойной щелчок по серверу (или Enter). Где откроется сессия, задаётся в Настройки → Терминал:

  • Встроенный терминал — вкладки в окне Quaykeep с подсказками из истории сервера, команд, файлов, контейнеров и служб; edit ФАЙЛ открывает файл во встроенном редакторе. По умолчанию в macOS и Linux.
  • Windows Terminal (вкладка или окно) или окно консоли — Windows.
  • Системный терминал — Terminal.app в macOS; в Linux $TERMINAL или первый из x-terminal-emulator, gnome-terminal, konsole, xfce4-terminal, kitty, alacritty, wezterm, foot, xterm.

Серверы с jump-хостом или дополнительными параметрами ssh всегда открываются во внешнем терминале (им нужен OpenSSH). Пароль передаётся ssh через SSH_ASKPASS, ключ — через агент: ни то ни другое не попадает в командную строку и на диск.

SSH-агент

Пока Quaykeep работает, его агент отдаёт ключи из хранилища программам ssh, git, VS Code Remote-SSH и всем, кто говорит на протоколе агента OpenSSH. Пока хранилище заблокировано, запрос открывает окно разблокировки. Точный адрес агента показан в строке состояния главного окна.

Windows

Агент занимает стандартный канал \\.\pipe\openssh-ssh-agent, с которым ssh.exe, git и VS Code работают без настройки. Если его уже занял другой агент (1Password, служба Windows «OpenSSH Authentication Agent»), Quaykeep использует \\.\pipe\quaykeep-agent-<пользователь>; укажите его программам так:

[Environment]::SetEnvironmentVariable('SSH_AUTH_SOCK', '\\.\pipe\quaykeep-agent-пользователь', 'User')

macOS

Агент — сокет ~/.quaykeep-agent.sock. Добавьте в ~/.zshrc:

export SSH_AUTH_SOCK="$HOME/.quaykeep-agent.sock"

или, только для ssh, в ~/.ssh/config:

Host *
  IdentityAgent ~/.quaykeep-agent.sock

Linux

Сокет — $XDG_RUNTIME_DIR/quaykeep-agent.sock (обычно /run/user/1000/…), без XDG_RUNTIME_DIR — ~/.quaykeep-agent.sock. Добавьте в ~/.bashrc / ~/.zshrc:

export SSH_AUTH_SOCK="$XDG_RUNTIME_DIR/quaykeep-agent.sock"

Сессии, запущенные из Quaykeep, получают нужный агент сами, что бы ни было в настройках оболочки.

Команда qk

qk <сервер> подключается к сохранённому серверу прямо в текущем терминале, qk list показывает список, qk cron <сервер> — задания по расписанию. Команда обращается к запущенной программе (и запускает её в трее, если нужно).

ОСГде qkКак сделать командой
Windows%LOCALAPPDATA%\QuaykeepApp\current\qk.exeдобавить эту папку в PATH
macOS/Applications/Quaykeep.app/Contents/MacOS/qksudo ln -s /Applications/Quaykeep.app/Contents/MacOS/qk /usr/local/bin/qk
Linuxвнутри AppImagealias qk="$HOME/Applications/Quaykeep-linux-x64.AppImage qk" в ~/.bashrc

Точный путь к помощнику вашей копии — в Настройки → Терминал.

ИИ-агенты (MCP)

Включается в Настройки → ИИ-агенты (MCP). Там же готовая команда для вашей копии с кнопкой «Копировать»; для справки:

# Claude Code — Windows
claude mcp add --scope user quaykeep -- "%LOCALAPPDATA%\QuaykeepApp\current\qk.exe" mcp
# Claude Code — macOS
claude mcp add --scope user quaykeep -- "/Applications/Quaykeep.app/Contents/MacOS/qk" mcp
# Claude Code — Linux (AppImage)
claude mcp add --scope user quaykeep -- "$HOME/Applications/Quaykeep-linux-x64.AppImage" qk mcp
# Codex — ~/.codex/config.toml (пример для macOS)
[mcp_servers.quaykeep]
command = '/Applications/Quaykeep.app/Contents/MacOS/qk'
args = ["mcp"]
tool_timeout_sec = 900

Затем для каждого сервера выберите, что можно агенту: правый щелчок → Доступ для ИИ-агента ▸ (по умолчанию выключен; только чтение, чтение и перезагрузка, команды меню, полный доступ). Перезагрузка и удаление сначала спрашивают вас, каждый вызов виден в журнале агента. Для клиентов, которые не умеют запускать программу, есть ещё HTTP на 127.0.0.1 с токеном.

Обновления

Раз в день Quaykeep проверяет релизы этого проекта на GitHub (в Настройки → Обновления есть «Проверить обновления» и «Обновить и перезапустить»). Установленные копии скачивают только изменения; обновление применяется при перезапуске. Папка данных в обновление никогда не входит.

Данные, бэкапы, переезд на другой компьютер

КопияПапка данных
Windows, установщик%LOCALAPPDATA%\Quaykeep\data
Windows, zipdata рядом с программой
macOS~/Library/Application Support/Quaykeep/data
Linux~/.local/share/Quaykeep/data

QUAYKEEP_DATA=/путь задаёт другую папку. Настройки → Бэкап упаковывает всю папку в архив в локальной папке или на сервере по SFTP (вручную или каждые N часов). Чтобы переехать на другой компьютер — в любой ОС — установите там Quaykeep и выберите Файл → Восстановить из бэкапа с вашим мастер-паролем.

Удаление

  • Windows: Параметры → Приложения → Quaykeep → Удалить. Папка данных остаётся; удалите %LOCALAPPDATA%\Quaykeep, чтобы убрать и её.
  • macOS: выйдите через строку меню, перенесите /Applications/Quaykeep.app в Корзину и при желании удалите ~/Library/Application Support/Quaykeep и ~/Library/LaunchAgents/app.quaykeep.plist.
  • Linux: выйдите через трей, удалите AppImage, ~/.local/share/Quaykeep и ~/.config/autostart/quaykeep.desktop.

Если что-то не так

  • Во встроенном терминале сообщение о веб-движке — Windows: установите WebView2 Runtime (есть в Windows 11); Linux: установите WebKitGTK (см. выше); или выберите другой терминал в настройках.
  • Нет значка в трее в GNOME — включите расширение AppIndicator; окно открывается и через меню приложений.
  • «Блокировать, когда блокируется компьютер» не срабатывает в Linux — программа слушает хранитель экрана и logind по D-Bus; большинство окружений их отправляют, некоторые минимальные оконные менеджеры — нет.
  • Глобальная клавиша (Win+Alt+X) есть только в Windows.
  • Что-то ещё? Напишите в issues.
