# Quaykeep SSH Manager

[English](README.md) | Русский

Quaykeep — личный Windows-инструмент для работы с большим количеством SSH-серверов:
хранение серверов, паролей и ключей в зашифрованном хранилище, запуск сессий в один клик,
автоматический перевод сервера с пароля на ключ и встроенный SSH-агент (аналог Pageant для OpenSSH),
который живёт в трее и стартует вместе с Windows.

## Установка

Скачайте `Quaykeep-X.Y.Z-win-x64.zip` со страницы [Releases](https://github.com/nickolsky/quaykeep/releases),
распакуйте в любую папку (например `C:\Tools\Quaykeep`) и запустите `Quaykeep.exe`.
Нужен [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) (x64) и системный OpenSSH-клиент
(есть в Windows 10/11). Данные хранятся в папке `data` рядом с программой.

**Обновления**: программа раз в день проверяет релизы на GitHub (Настройки → Обновления, там же «Проверить обновления»
и «Обновить и перезапустить»). Архив сверяется по SHA-256, заменяются только файлы программы — `data` не трогается;
занятые файлы (например, `qk.exe` в открытом терминале) переименовываются в `*.sshm-old` и удаляются при следующем запуске.

## Сборка из исходников

```powershell
.\publish.ps1                 # сборка в .\app (данные — в .\data рядом с Quaykeep.sln)
.\app\Quaykeep.exe            # первый запуск — создание мастер-пароля
.\publish-dev.ps1             # тестовая копия в .\app-dev со своими данными, работает рядом с основной
.\release.ps1 [-Publish]      # артефакт релиза artifacts\Quaykeep-<версия>-win-x64.zip (+ .sha256) и GitHub-релиз
```

Версия задаётся в `Directory.Build.props` (`<Version>`), тег релиза — `v<версия>`.

## Переход с SSH Manager

До версии 1.0.1 Quaykeep назывался **SSH Manager** (программа `SshManager.exe`, консольный помощник `sshm.exe`).
Версия 1.0.1 не может сама обновиться до Quaykeep, поэтому один раз — вручную: закройте SSH Manager из трея, распакуйте
архив Quaykeep в ту же папку и запустите `Quaykeep.exe`. Папка `data`, хранилище и настройки используются как есть; старые
файлы программы и старая запись автозапуска удаляются при первом запуске. Что, возможно, придётся сделать самому:

- **ИИ-агенты**: помощник теперь `qk.exe`. Зарегистрируйте MCP-сервер заново командой из «Настройки → ИИ-агенты (MCP)»
  (например, `claude mcp remove sshmanager`, затем `claude mcp add … quaykeep -- "…\qk.exe" mcp`).
- **Консоль**: `qk <сервер>` вместо `sshm <сервер>`.
- **`SSH_AUTH_SOCK`**: если он указывает на `\\.\pipe\sshmanager-agent-<пользователь>`, этот pipe продолжает работать;
  новое имя — `quaykeep-agent-<пользователь>`.
- `SSHMANAGER_DATA` / `SSHMANAGER_INSTANCE` по-прежнему работают; новые имена — `QUAYKEEP_DATA` / `QUAYKEEP_INSTANCE`.
- Старые копии `sshmanager-data-*.zip` можно восстановить, и ротация учитывает их вместе с новыми `quaykeep-data-*.zip`.

На серверах ничего не меняется: переменные скриптов (`SSHM_RESULT`, `SSHM_HOST`…), `/tmp/sshm-*`, `~/.cache/sshm` и метки
`sshm` в `sshd_config` и комментариях iptables сохраняют имена, так что прежние установки и пробросы по-прежнему узнаются.

При первом запуске программа попросит придумать мастер-пароль и предложит автозапуск
(галочка включена по умолчанию; меняется в «Настройки»). При автозапуске программа стартует сразу в трей
**заблокированной**; окно разблокировки появится при первом обращении к серверу или агенту.

## Возможности

- **Серверы**: название, группа, хост/IP, порт, пользователь, пароль или ключ, jump-хост, доп. аргументы ssh, заметки.
  Дерево с вложенными группами (`VPN/Европа`), которые сворачиваются и запоминаются; поиск (Ctrl+F) — в том числе
  по ОС, региону и контейнерам; двойной клик / Enter — подключиться, Ctrl+N — новый сервер, F5 — обновить всё.
- **Меню сервера** (правый клик) сгруппировано: подключение, изменение, копирование, дублирование → установка, пробросы,
  ключи, ИИ-агенты → пинг, проверки, мониторинг, история → перезагрузка, удаление. **«Копировать ▸»**: имя хоста (для IP —
  через обратный DNS), IP-адрес (для имени — определяется через DNS с этого ПК), пароль (не попадает в журнал буфера
  обмена Windows и стирается из буфера через 30 секунд), публичный ключ, команда ssh и адреса `http://` / `https://`,
  если на сервере открыт порт 80 / 443 / 8080 / 8443.
- **Пинг…**: ICMP-пинг с этого ПК раз в секунду в отдельном окне — время, TTL, потери, мин / ср / макс. Многие VPN-серверы
  не отвечают на ICMP, поэтому для мониторинга он не используется; если ответов нет, окно показывает состояние SSH-порта.
- **Трассировка…**: путь по узлам — с этого ПК до сервера (как `tracert`) или **с сервера** по SSH до этого ПК, другого
  сервера или любого адреса (`traceroute`, устанавливается, если его нет, или `tracepath`).
  - **У каждого узла** — обратное DNS-имя, сеть (AS и провайдер) и расположение. Адреса узлов запрашиваются одним
    пакетом в ip-api.com.
  - **Под таблицей** — что видно по маршруту:
    - путь по провайдерам («Домашний провайдер (Москва, RU) → Магистраль (Франкфурт, DE) → Хостер (Фалькенштайн, DE)»);
    - страны по пути;
    - где самый большой прирост задержки (обычно дальний канал);
    - узлы, чьё расположение по GeoIP не сходится со временем ответа (на 100 км нужна минимум 1 мс туда и обратно), —
      они помечены «?» и не входят в путь;
    - неответившие узлы, достигнута ли цель, и замечание, если VPN на этом ПК отвечает за любой адрес.
- **Whois…**: хостер, сеть (AS, организация, домен) и запись регистратора об IP-адресе сервера (RDAP: сеть и её имя,
  владелец и его адрес, контакт для жалоб, даты), а также полная текстовая запись с whois-сервера регистратора (порт 43).
  - Читается один раз на адрес, снова — при смене IP, по «Обновить» или «Обновить данные».
  - **Найти панель управления**: поиск в Google страницы входа в панель управления хостера.
- **«Проверить доступность сейчас»** и **«Проверить подключение»**: первое — только TCP-подключение к SSH-порту (ответ sshd)
  и отслеживаемым портам, без входа на сервер, результат идёт в историю доступности; второе — полный вход по SSH
  с сохранённым паролем или ключом и команда `uname -a`, результат показывается в окне.
- **Русский / English**: меню «Язык (Language)», меню трея или «Настройки» — переключается сразу, без перезапуска.
- **Мониторинг доступности**: TCP-подключение к SSH-порту и ответ sshd, по умолчанию раз в 5 минут (интервал
  меняется глобально и для каждого сервера: правый клик → «Мониторинг ▸» — каждую минуту … раз в сутки или
  «Не проверять»). Если SSH не отвечает, но открыт хотя бы один отслеживаемый порт,
  сервер считается доступным (жёлтая точка). Цветная точка в дереве, уведомление в трее, когда сервер падает.
- **Аптайм**: каждая проверка пишется в `data\uptime`, колонка «Аптайм» показывает доступность за сутки / неделю /
  30 дней. «История доступности…» в контекстном меню — графики доступности и задержки за 24 ч … год и список
  отключений. Время, когда программа не работала, не считается ни доступностью, ни простоем.
- **Мониторинг портов**: для сервера отмечаются TCP-порты (443 VPN, 2053 панели…) — вручную или из найденных
  на сервере (`ss -tlnp`): «Мониторинг портов…» или «Следить за этим портом» в контекстном меню. Порт, который
  перестал отвечать, красный в колонке «Порты», сервер — жёлтый, в трее уведомление. Для порта с пробросом
  проверяется вся цепочка до целевого сервера. UDP не проверяется: у UDP нет подключения, и закрытый порт снаружи
  не отличить от открытого.
- **Пробросы портов** (iptables DNAT, кнопка «Пробросы портов»): добавить, изменить (двойной щелчок по строке —
  старый проброс удаляется и новый создаётся одним скриптом; если новый не встал, старый возвращается), удалить.
  Галочка «Мониторинг» в строке ставит порт на проверку. Пробросы через несколько серверов видны цепочкой:
  `A:443 → B:8443 → C:443 (nginx)` — в окне, на карте сети и в подсказке у проброса в дереве.
  «Перейти к …» в меню проброса (или двойной щелчок) переходит к серверу на другом конце, прямо к следующему звену.
- **CPU / память / диск**: после каждой успешной проверки программа заходит по SSH и читает `/proc`
  (колонки CPU, «Память» и «Диск» — свободное место на `/`; подсказка — load, диск, время работы).
- **Что на сервере**: при первом подключении (и при раскрытии сервера, если данные старше 10 минут) определяются
  дистрибутив Linux, Docker-контейнеры, известные сервисы (nginx, Xray, 3X-UI, WireGuard, OpenVPN, Marzban…),
  слушающие порты и пробросы iptables. Всё видно в раскрытом сервере; для контейнеров и сервисов — логи,
  статус и перезапуск в терминале.
- **Задания по расписанию**: раздел «Cron и таймеры» у сервера — crontab всех пользователей, `/etc/crontab`,
  `/etc/cron.d`, скрипты `cron.hourly…monthly` и таймеры systemd (расписание, следующий запуск). В меню строки:
  копировать, открыть файл в редакторе, `crontab -e` в терминале, статус и журнал таймера. В консоли — `qk cron <сервер>`.
- **Перезагрузка**: кнопка «Перезагрузить» (и пункт меню сервера) после подтверждения; программа ждёт, пока сервер
  вернётся, и сообщает в трее, через сколько секунд он снова в сети (или что не вернулся за 10 минут).
- **Регион** и **Хостер**: страна и город по IP и кто держит сеть — организация, стоящая за AS, иначе владелец блока
  адресов из whois. Данные берутся из онлайн-сервиса ipwho.is (запасной — ip-api.com), кэш 30 дней; whois — у регистраторов
  через rdap.org, один раз на адрес. Отключается. В подсказке — AS, домен, владелец блока и контакт для жалоб.
- **Пробросы портов (iptables)**: «Пробросы портов…» показывает существующие DNAT-правила и добавляет новые
  (`443 → другой сервер:443`, tcp/udp, диапазоны): DNAT + MASQUERADE + FORWARD, `ip_forward`, сохранение через
  netfilter-persistent / iptables-save (при необходимости предлагает поставить iptables-persistent).
  Пробросы видны в основном дереве — и исходящие, и входящие.
- **Файрвол** («Файрвол…» в меню сервера, «Файрвол для группы…» в меню группы): **заблокировать** выбранные IP и сети
  или **разрешить только им** — для портов (tcp/udp, списки, диапазоны) или для всего сервера; IPv4 и IPv6.
  - **Что закрывается:** порты, опубликованные контейнерами Docker, и пробросы тоже — Docker здесь не обходит защиту,
    как обычно обходит ufw.
  - **Порядок:** блокировки → «только этим IP» для портов → «только этим IP» для всего сервера. Loopback, уже открытые
    соединения, DHCP и ICMPv6 пропускаются всегда, так что сервер не потеряет адрес.
  - **Только ограничивает:** то, что закрыто собственным файрволом сервера (ufw, firewalld), Quaykeep не открывает.
  - **Безопасное применение:** правила ставятся вместе с таймером на сервере, который вернёт прежние, и остаются, только
    если *новый* вход по SSH работает. Если правила закрыли бы SSH для этого ПК, окно предупредит заранее.
  - **Сохранение** — в `quaykeep-firewall.service`, после перезагрузки правила возвращаются.
  - **Адреса:** «+ этот ПК», «+ все» (`0.0.0.0/0` и `::/0`) или «+ сервер ▾» — IP другого сервера из списка; Quaykeep
    запоминает, что адрес принадлежит этому серверу.
  - **Пресеты:** именованные наборы правил (например «SSH только из офиса») хранятся один раз и отмечаются у серверов.
    Сервер получает свои правила плюс свои пресеты; изменение пресета применяется на всех его серверах.
  - **Несколько серверов:** «Копировать на серверы…» (добавить или заменить) или окно группы.
  - **Смена IP сервера:** когда вы сохраняете новый хост в редакторе сервера, Quaykeep показывает правила файрвола
    (связанные с сервером или с тем же адресом, введённым вручную) и **пробросы портов** на других серверах, которые
    указывают на старый IP, и обновляет и применяет их одним действием.
  - **На сервере** правила живут в собственных цепочках iptables `QK-IN` / `QK-FWD`; «Отключить файрвол…» удаляет их.
  - **Прокси:** клиенты за CDN или прокси приходят с адресом прокси.
- **Карта сети** (кнопка «Карта сети», Ctrl+M, «Показать на карте сети» в меню сервера): пробросы портов всех серверов
  схемой. Серверы и адреса, куда идут пробросы, — узлы; каждый проброс — стрелка с подписью `tcp 443 → 8443`.
  - **Маршруты:** щелчок по стрелке подсвечивает весь маршрут, от места, куда подключаются клиенты, до того, что
    слушает в конце (nginx, контейнер…). Боковая панель перечисляет все участки.
  - **Файрвол на карте:** пробросы делают MASQUERADE, поэтому каждый сервер видит адрес предыдущего. Каждый участок
    проверяется по правилам Quaykeep на следующем сервере: зелёный — пропускает, красный — отбрасывает (панель
    называет правило), жёлтый — зависит от неизвестного адреса. Щит там, куда подключаются клиенты, показывает, кому
    это разрешено.
  - **Частные сети:** инвентаризация читает адреса интерфейсов серверов, поэтому проброс на `10.0.0.3` приходит на
    тот сервер, у которого этот адрес в сети отправителя. Такой же частный адрес в другом месте — другой хост.
  - **Связи:** потяните от кружка сервера к другому серверу (или в пустое место — для любого адреса), чтобы
    запланировать проброс. Форма проверяет порты по существующим пробросам и по порту SSH. Если список разрешённых
    адресов у цели отбросит новый участок, она предлагает добавить адрес отправителя в это правило.
  - **План, потом «Применить»:** запланированные пробросы (пунктир), пробросы на удаление и добавления в файрвол ждут
    в плане. «Применить» сначала применяет файрвол (с обычной проверкой входа), потом удаляет пробросы, потом
    добавляет новые; то, что не удалось, остаётся в плане.
  - **Расположение:** автоматическое, по колонке на участок. Узлы можно перетаскивать (положение хранится в vault);
    «Расставить» раскладывает заново.
- **Установочные скрипты**: «Настройки → Установочные скрипты» (хранятся в зашифрованном vault), запуск — правым
  кликом «Установить ▸». Скрипт выполняется в окне программы: форма параметров, живой вывод, результаты
  сохраняются у сервера (раздел «Результаты скриптов» в дереве, «Копировать значение»); ссылки (`vless://`,
  `hysteria2://`, ключи `vpn://`, адреса сайтов) можно показать QR-кодом для телефона — «Показать QR-код». Для интерактивных
  установщиков есть кнопка «В терминале». ОС скрипта выбирается в выпадающем списке (несколько, можно с версией:
  `debian:12`), скрипты для ОС сервера показываются первыми.
  Встроенные скрипты (в меню разложены по группам):

  | Группа | Скрипт | Что получается |
  |---|---|---|
  | VPN | **VLESS REALITY** (Xray в Docker) — Ubuntu и CentOS; Debian 12 с маленьким диском | ссылка `vless://…`, порт на мониторинге |
  | VPN | **Hysteria 2** (официальный образ): самоподписанный сертификат с pinSHA256 или Let's Encrypt, obfs Salamander | ссылка `hysteria2://…` |
  | VPN | **AmneziaWG** (официальный `amneziavpn/amneziawg-go`, без модуля ядра, от 512 МБ памяти); клиенты по именам: `phone,laptop` | ключ `vpn://` для Amnezia VPN на каждого клиента, QR-код конфига (AmneziaWG и Amnezia VPN), `.conf` в `/opt/amneziawg/clients` |
  | Веб-сервер | **Статический сайт — nginx без Docker**, HTTPS через certbot | папка `/var/www/sshm-site` |
  | Веб-сервер | **Статический сайт — Caddy в Docker**, с доменом HTTPS включается сам | папка `/opt/static-site/site` |
  | Облачные хранилища | **Nextcloud** (+ PostgreSQL, Redis, cron; HTTPS через Caddy при домене) | адрес, логин и пароль администратора |
  | Облачные хранилища | **Seafile 13** (+ MariaDB, Redis; HTTPS через Caddy при домене) | адрес, логин и пароль администратора |
  | Облачные хранилища | **File Browser** — веб-доступ к папке, от 256 МБ памяти | адрес, логин и пароль администратора |
  | Передача файлов | **SFTP-пользователь** через уже установленный OpenSSH: только SFTP, chroot в своей папке, пароль и/или ключ (пароль можно оставить только ему, даже если на сервере он выключен) | адрес `sftp://`, логин и пароль |
  | Передача файлов | **FTP / FTPS (vsftpd)** для камер, сканеров и старых клиентов: по умолчанию только с TLS (Let's Encrypt по домену или самоподписанный), chroot, пассивные порты | адрес `ftp://`, логин и пароль, порт на мониторинге |
  | — | **Docker Engine + Compose**, **Uptime Kuma** (Docker Compose) | версии / адрес |

  Новые скрипты — для Ubuntu 22.04+, Debian 12+ и CentOS Stream / Rocky / AlmaLinux / RHEL 8+ (проверяются на тестовом
  стенде). На CentOS пакеты ставятся через dnf (чего нет в основных репозиториях — из EPEL), Docker — из репозитория
  download.docker.com, для nginx настраивается SELinux. Повторный запуск сохраняет ключи, пароли и данные
  (ссылки не меняются), порты открываются только в уже включённом firewall (ufw, firewalld или iptables). Для Nextcloud и Seafile на серверах
  с памятью меньше 2 ГБ создаётся swap. VLESS REALITY взят из
  [vless_docker_install_scripts](https://github.com/nickolsky/vless_docker_install_scripts). Как проверить скрипты
  на тестовых серверах — [tools/script-lab](tools/script-lab/README.md).
- **Резервное копирование**: zip всей папки `data` в папку на диске или на сервер по SFTP, ротация, автобэкап раз
  в N часов, кнопка «Сделать бэкап сейчас». **Восстановление** — «Восстановить из копии…» (Настройки → Резервное
  копирование или меню «Файл»): последняя копия из папки/с сервера или любой `quaykeep-data-*.zip`, нужен мастер-пароль
  на момент бэкапа; текущие данные перед заменой сохраняются в `data\backups\before-restore-*.zip`.
- **Подключение в один клик**: сессия открывается во вкладке Windows Terminal (или новом окне / обычной консоли —
  см. настройки). По ключу — через встроенный агент, по паролю — пароль подставляется автоматически через
  `SSH_ASKPASS`. Ни пароль, ни приватный ключ не попадают в командную строку и на диск.
- **Встроенный терминал** (Настройки → Терминал → «Встроенный терминал»): сессии во вкладках окна программы
  (xterm.js). Для bash / zsh подгружается интеграция из `~/.cache/sshm` (файлы rc не меняются): подсказки при наборе —
  история сервера, команды, подкоманды и флаги docker / compose / systemctl / journalctl / apt / git / ufw…, файлы,
  контейнеры, сервисы, пакеты; серая подсказка из истории (→ принять), Ctrl+Space — список вручную, Tab — вставить.
  Команда `edit ФАЙЛ` открывает файл во встроенном редакторе, Ctrl+Shift+F — файлы в текущей папке.
- **Файловый менеджер (SFTP)**: кнопка «Файлы» — две панели в стиле Far, компьютер и сервер; F5 копировать,
  F6 переместить, F7 папка, F8 удалить, F2 переименовать, F4 редактировать; Insert / Shift+стрелки — отметить файлы,
  Num + / Num − — отметить / снять по маске (`*.yml;*.conf`), Num * — инвертировать, Ctrl+клик / Shift+клик, Shift+правый клик (с протяжкой — по нескольким);
  перетаскивание между панелями и из проводника, очередь передач с прогрессом и отменой, права (chmod).
- **Редактор** (CodeMirror 6): подсветка shell / yaml / json / nginx / ini / Dockerfile…, поиск и замена, Ctrl+S.
  Кодировка и переводы строк сохраняются как были; файл, изменённый на сервере, не перезаписывается молча;
  без прав на запись — сохранение через sudo (владелец и права файла остаются прежними).
- **«Настроить вход по ключу»**: входит по сохранённому паролю, генерирует Ed25519-ключ (или берёт существующий),
  добавляет его в `~/.ssh/authorized_keys` (без дублей, права 700/600), проверяет вход по ключу и переключает сервер
  на ключ. По галочке **«Отключить вход по паролю»** — и только если вход по ключу уже проверен — программа выключает
  `PasswordAuthentication` в sshd (файл `/etc/ssh/sshd_config.d/00-sshm-no-password.conf` или блок в начале
  `sshd_config`), проверяет настройки `sshd -t` / `sshd -T` до перезагрузки sshd, затем заново входит по ключу; если вход
  не удался, через ещё открытое соединение вход по паролю возвращается. Нужен root или sudo; сохранённый пароль остаётся
  (он нужен для sudo).
- **Ключи**: генерация Ed25519 / RSA-4096, импорт (OpenSSH, PEM, PuTTY .ppk, в т.ч. с passphrase),
  копирование публичного ключа, экспорт приватного (файл доступен только вашему пользователю Windows).
- **Проверка ключей серверов**: при первом подключении показывается отпечаток ключа сервера; изменение ключа
  выдаётся как предупреждение. Используется собственный `data\known_hosts`.
- **Трей**: быстрый доступ к серверам (меню «Подключиться»), блокировка, выход. Кнопка закрытия окна сворачивает в трей.
- **Горячая клавиша** **Win+Alt+X** (во всей системе) показывает окно, повторное нажатие прячет его; меняется или
  выключается в «Настройки → Интерфейс» (щёлкните поле и нажмите сочетание).
- **Автоблокировка**: после N минут простоя ПК (по умолчанию 120) и, по желанию, при Win+L.
- **Консоль**: `qk <имя сервера>` подключает к сохранённому серверу прямо в текущем терминале,
  `qk list` — список серверов, `qk cron <сервер>` — задания по расписанию. Добавьте папку `app` в PATH,
  чтобы вызывать `qk` откуда угодно.
- **ИИ-агенты (MCP)** — Claude Code, Codex и другие могут управлять серверами через Quaykeep, см. ниже.

## ИИ-агенты (MCP)

Quaykeep работает как MCP-сервер: агент вызывает его инструменты, а команды выполняет программа с паролями и
ключами из хранилища — агенту они не передаются. Включается в «Настройки → ИИ-агенты (MCP)», там же готовые
команды подключения с кнопкой «Копировать»:

```powershell
claude mcp add --scope user quaykeep -- "D:\…\app\qk.exe" mcp          # Claude Code (stdio)
```

```toml
# Codex: ~/.codex/config.toml
[mcp_servers.quaykeep]
command = 'D:\…\app\qk.exe'
args = ["mcp"]
tool_timeout_sec = 900
```

По желанию — ещё и HTTP на `127.0.0.1` (Streamable HTTP, токен в заголовке `Authorization: Bearer …`, чужие
`Origin` / `Host` отклоняются). Если программа не запущена, `qk mcp` запускает её в трее; заблокированное
хранилище агент попросит разблокировать.

**Что можно агенту, задаётся у каждого сервера** («Изменить…» → «Доступ для ИИ-агента» или меню «Доступ ИИ-агента ▸»);
каждый уровень включает предыдущие:

| Уровень | Инструменты |
|---|---|
| Выключен (по умолчанию) | сервер не виден агенту |
| Только чтение | `list_servers`, `server_status` (доступность, CPU / память / диск, аптайм), `list_containers`, `list_services`, `list_cron_jobs`, `list_ports`, `list_firewall`, `container_logs`, `service_logs` |
| Чтение и перезагрузка | + `reboot_server` |
| Команды из меню | + `container_action` (start / stop / restart / автозапуск / удалить), `service_action`, `refresh_info`, `list_install_scripts`, `run_install_script` + `get_job` |
| Полный доступ | + `run_command` (в т. ч. sudo), `list_directory`, `read_file`, `write_file`, `delete_path`, `upload` / `download` — только в разрешённые локальные папки сервера, `script_results`, `add_firewall_rule` / `remove_firewall_rule` (с вашим подтверждением; правило, которое отрезало бы SSH Quaykeep, не принимается) |

- Перезагрузку и удаление (контейнера, файла, папки), а также остановку SSH программа сначала показывает окном
  «Разрешить / Отклонить» (без ответа 2 минуты — отказ; отключается в настройках).
- Системные папки (`/`, `/etc`, `/usr`…) агенту удалять нельзя ни на каком уровне.
- **Учётные данные из скриптов** видны только при полном доступе — в `script_results`, `get_job` и в выводе задания.
  Это пароли, ключи, токены и ссылки для входа (`vless://`, `hysteria2://`, `vpn://` или адрес с `user:password@`).
  - Флажок в настройках «Никогда не показывать агентам пароли, ключи и ссылки для входа из скриптов» скрывает их
    и при полном доступе.
  - С полным доступом агент всё равно может прочитать их на самом сервере (`run_command`, `read_file`), поэтому для
    строгой защиты давайте ему доступ ниже полного.
- Серверы за jump host / с доп. параметрами ssh агенту недоступны (кроме статуса).
- **Журнал** всех вызовов, в том числе отклонённых: «Журнал агента…» в меню сервера или в настройках — в реальном
  времени, по серверу или по всем. Вид «Консоль» показывает журнал как терминал: у каждого вызова приглашение
  с именем агента и сервера, команда (`#` — через sudo) и её вывод в цвете, ошибки и отказы красным;
  вид «Строки» — строки файла как есть. Файлы в `data\agent-logs`: новый файл каждый день и при переполнении, общий
  объём на сервер и срок хранения задаются в настройках. В резервные копии журнал не входит.

## SSH-агент

Агент поднимается на named pipe `\\.\pipe\openssh-ssh-agent` — это стандартный адрес, который используют
`ssh.exe`, `git`, VS Code Remote-SSH. Если этот pipe уже занят другим агентом (например, **1Password** или
служба Windows `ssh-agent`), Quaykeep использует `\\.\pipe\quaykeep-agent-<пользователь>`.
Сессии, запущенные из Quaykeep, работают в обоих случаях. Чтобы внешние программы тоже брали ключи
из Quaykeep, освободите стандартный pipe (например, отключите SSH-агент в 1Password) или задайте
переменную окружения пользователя:

```powershell
[Environment]::SetEnvironmentVariable('SSH_AUTH_SOCK', '\\.\pipe\quaykeep-agent-<пользователь>', 'User')
```

Точный адрес агента показан в строке состояния главного окна. Пока хранилище заблокировано, агент ключей
не отдаёт (при обращении клиента показывается окно разблокировки — отключается в настройках).

## Данные и безопасность

Все данные лежат в папке `data`: рядом с `Quaykeep.exe`, а в исходниках — рядом с `Quaykeep.sln` (папка в `.gitignore`):

| Файл | Содержимое |
|---|---|
| `vault.dat` | серверы, пароли, приватные ключи — AES-256-GCM, ключ из мастер-пароля через Argon2id (64 МБ, 3 итерации) |
| `backups\` | 20 последних версий `vault.dat` и снимки `before-restore-*.zip` перед восстановлением |
| `settings.json` | настройки интерфейса (без секретов) |
| `known_hosts` | ключи серверов в формате OpenSSH |
| (в `vault.dat`) | собранные сведения о серверах (ОС, контейнеры, регион), отслеживаемые порты, установочные скрипты |
| `pub\` | публичные ключи (нужны `ssh.exe`, чтобы выбрать нужный ключ из агента) |
| `uptime\` | история проверок доступности (CSV на сервер: время, состояние, задержка), хранится 400 дней |

Резервная копия = копия папки `data` + мастер-пароль (раздел «Резервное копирование» делает это автоматически;
для восстановления распакуйте архив в папку `data`). **Забытый мастер-пароль восстановить нельзя.**
Папку данных можно переопределить переменной окружения `QUAYKEEP_DATA`.

## Свои скрипты с параметрами и результатами

Параметры и результаты описываются комментариями в самом скрипте — по ним строится форма запуска:

```bash
#!/usr/bin/env bash
# @name    Мой сервис
# @os      ubuntu,debian:12
# @group   VPN                                              # подменю в «Установить ▸» (VPN, Web, Cloud, Files или своё)
# @description Что делает скрипт (показывается в окне запуска; @description_en — по-английски)
# @param   DOMAIN  text   required label="Домен" default=example.com hint="Подсказка под полем"
# @param   MODE    choice options=fast,safe default=safe label="Режим"
# @param   PATH_X  text   default=/x when=MODE=fast          # поле видно только при MODE=fast
# @param   PORT    number default=8443 label="Порт"
# @param   DEBUG   bool   label="Подробный вывод"            # 1 / 0
# @param   TOKEN   secret label="Токен"                      # скрыто при вводе, не сохраняется в истории
# @result  URL     label="Ссылка"
# @result  PORT    label="Порт" monitor=MyService            # значение-порт ставится на мониторинг
# @result  KEY_*   label="Ключ"                              # KEY_phone, KEY_laptop… (исчезнувшие удаляются)
set -euo pipefail
echo "Ставлю на $SSHM_SERVER_NAME ($SSHM_HOST): $DOMAIN $MODE"
echo "URL=https://$DOMAIN:$PORT" >> "$SSHM_RESULT"
echo "PORT=$PORT" >> "$SSHM_RESULT"
```

Параметры приходят переменными окружения (через файл в личной папке `/tmp/sshm-*`, не через командную строку), `label_en=` / `hint_en=`
задают английский текст. Результат — строки `ИМЯ=значение` в файле `$SSHM_RESULT`; последние значения видны у сервера,
история запусков (параметры без секретов, код выхода, хвост вывода) тоже хранится в vault.

## Структура решения

```
src/Quaykeep.Core   хранилище, криптография, форматы ключей, SSH-агент, IPC, запуск ssh, настройка ключей (SSH.NET),
                      строки RU/EN, мониторинг, метрики, инвентаризация, GeoIP, iptables, скрипты, бэкап
src/Quaykeep        WPF-приложение: окна, дерево серверов, трей, автозапуск, автоблокировка
src/qk              консольный помощник: вкладка терминала, SSH_ASKPASS, `qk <сервер>`
tests/Quaykeep.Tests  unit-тесты + совместимость с ssh-keygen/ssh-add + e2e
```

Тесты: `dotnet test`. Сквозной тест с настоящим sshd включается переменной
`SSHM_E2E=host:port:user:password` (используйте одноразовый тестовый сервер/контейнер; для проверки
пробросов нужен root и `--cap-add NET_ADMIN`). Как работать с кодом через ИИ-агента — [AGENTS.md](AGENTS.md).
